# 上限与卡点 / Limits

On-device **face pose + ear-ROI quality peak search**. Not medical meatus imaging; not the same absolute yaw for everyone. We pick the clearest, highest-structure **stable** frame we can track while the user turns that side toward the camera.

Capture mode: `qualityPeakYaw` (`src/config/pose-config.json`). READY does **not** require yaw ∈ [70, 90]. A personal peak around **~45°** is allowed.

English twin: [LIMITS.md](./LIMITS.md).

## 一句话边界

用 MediaPipe 头部位姿做方向，用耳区 ROI 的清晰度/结构分做「这只耳朵对这个人够不够正」；在可跟踪的侧转范围内选峰值，而不是卡死 70–90°。

## 试过、只做到一半的

- **固定 70–90° READY：** 已弃用。位姿只做转向提示；READY 看个人 bestYaw。
- **问用户「你是不是 45° 那种」：** 不做。转头过程里自动记峰值。
- **专用耳 landmark / 3D 耳：** 未接。MediaPipe 脸部耳点在侧脸上不可靠，所以用头部位姿 + ROI 质量。触发条件：有稳定侧脸耳分割模型且延迟可接受。
- **扫过窗口 60% 才允许 READY：** 配了 `minSweepCoverageRatio`，**故意不作为硬门**。否则 45° 附近停住的清晰耳会被逼去转满窗。灰按钮文案是「先慢转过头」；假峰风险写在这里，不挡 READY。
- **45s 无进展超时：** 现在是退出叙事（`STUCK_NO_PROGRESS`），带 **再试一次** / **重新学习** / 拨开头发换亮一点。仍不是硬失败，也分不清原因（头发、光线、跟丢、假峰）。
- **外耳道暗斑惩罚：** 用 ROI 中心亮度做了很弱的启发；没有分割时分不清 meatus 和头发阴影。
- **耳朵出画：** 只是 ROI 被画面裁切的比例，不是真耳检测。框里但被头发挡住仍走「拨开头发」。
- **SOFT_READY 相对 READY：** 弱峰值或扫过一圈分数几乎不变的启发，不是「这肯定不是耳朵」的标定。过的是同一套质量门；软成功用黄色边框、单独的快门提示和拍完那一句。强峰值仍是绿色「可以拍了」。不是固定偏航角。自动快门照常倒计时。
- **多帧 burst 选最高分：** 倒计时仍等 3 帧 READY，然后拍当前帧；没有缓存 3 张再选最清晰的。

## 不做（Won't do）

- 固定 70–90 作为 READY 硬门
- 主路径等人按「耳朵已经正了」
- 在没有上表触发条件时上专用耳 landmark / 3D 耳模型

## 交互：上限 vs 做不到（文案）

用户可见字符串在 `src/i18n/`。未锁定时不会拿先验喊「再转一点点 / 往回一点」。学习中灰快门不会说「保持不动」。自动快门倒计时可取消。重新学习会再确认，只清这一侧。绝对角度只在调试开关后显示。

**文案上明确不做。** 不会教人人同一套 70–90（或 60–95）当 READY，也不会把重新学习写成「校准」。

## 当前 READY（实现）

1. 脸在框里、距离还行  
2. 这一侧已经有过 **bestYaw**（搜索窗内质量分最高的 yaw）  
3. 当前 yaw 在 bestYaw **±5°**（已就绪则保持到 **±8°**，`exitBandDeg`），pitch/roll 在 ready 限内  
4. 连续约 12 帧角度稳定  
5. 耳区分数 ≥ 该侧峰值的 **92%**，亮度 60–200  
6. 不要求 yaw ∈ [70, 90]；不要求用户确认  

引导：一条短提示，中英可切换。冷启动要先选身体的左/右耳（不是屏幕）再进 INTRO，选择会记住。切换左右仍会重置该侧快门、停留和引导，并显示身体左右的侧介绍；另一侧已记住的峰值保留。峰值还没锁定时只说扫转（不会拿先验角度喊「再转一点点 / 往回一点」）。`SLOW_DOWN`（「转慢一点」）在 yaw 猛跳时可抢占扫转提示，随后按短窗口 `slowDownHoldMs`=200（和 READY 的 `readyPromoteMs` 同一思路）让回 SWEEP，不会占满整段同族 `minDwellMs`。锁定后，过了 `bestYaw` 且分数掉了才说往回；往回走是 HOLD，不是 MORE。靠近已锁定峰值但还不稳定时，快门仍是灰的，文案用 **NEAR_PEAK**（「快到了…」），不用 **HOLD_STILL**（「保持不动」）。就绪滞回：进入 ±5° / 离开 ±8°。自动快门是 Ready 后可取消的 `autoshutterMs` 倒数。拍完按相对峰值给反馈（没有绝对度数），可重拍或拍另一只耳。绝对角度数字只在调试开关后显示。

## 做不到 + 突破条件（1–8）

1) 人人同一「标准角」
做不到：固定 70–90 当 READY。
要突破：人群侧脸分布数据后再收 preferred（仍非硬 READY）。

2) 医学外耳道 / 耳镜级
做不到：现在只优化耳廓清晰稳定帧。
要突破：另套 meatus ROI/模型 + 临床定义与知情同意。

3) 无假峰
做不到：无耳分割时头发/背景可赢过真耳廓。
要突破：侧脸耳分割或遮挡模型 + 按角度标注。

4) 窗外真峰（|yaw|<35 或 >90）
做不到：搜索窗外采不到；高 yaw 易跟丢。
要突破：FOV 标定扩窗；掉跟踪冻结 last-good / PnP。

5) 系统自动改选左右耳
做不到：产品约定用户点选；点错不自检。
要突破：可靠左右耳分类器（延迟可接受）。

6) 跨设备绝对清晰度阈值
做不到：Laplacian 绑相机/曝光。
要突破：开机模糊标定（平面/手掌）。

7) 自动判断「该重新学习」
做不到：不知发型/眼镜变化。
要突破：同人同机长期信号。

8) timeout 说不清「为什么卡住」
做不到：只能「这次没找到」+ 换光/拨发/重学。
要突破：可归因质量头或分割。

## 鸿蒙壳（打包上限）

不属于上面 1–8。只写发行上限，不是拍耳质量上限。

不能声称可上架，也不能写成官方支持的鸿蒙交付。

- **卡点：** HAP 需要 DevEco Studio 和签名。没有官方 Capacitor 鸿蒙路径。本仓库没有打出 HAP 的 CI。
- **当前上限：** 手机/Web 拍耳，加上已在 `main` 的 Android debug APK。树里没有鸿蒙包。
- **短板：** 鸿蒙上的相机权限、WebView、MediaPipe WASM 都未在本仓库验证。仓库外自留的本地壳不能当作已支持。
- **后续：** 在真正有 HAP 里程碑之前，上限只写在这里。不要用入库 `harmony/` 树或二进制代替该里程碑。
- **突破条件：** DevEco 环境就绪、签名证书、可安装的 HAP，以及真机上相机权限和拍摄流程确实能跑。应用市场上架是更后面的厂商发布步骤，这些条件不具备之前不做。
